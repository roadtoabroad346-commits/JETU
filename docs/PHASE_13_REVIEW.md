## Data, authorization and product

- Five forward migrations on top of Phase 10: `20261021154711_scholarship_explorer`, `20261021154759_scholarship_fk_indexes`, `20261021155015_scholarship_funding_truth`, `20261021155400_scholarship_save_visibility`, `20261021155940_scholarship_editor_rpc`. They add external-provider details, application/document requirements, editorial memberships/events/notes, student saves, funding coverage, IANA deadline timezone validation, indexed source search and a bounded public RPC. Existing canonical scholarship cycles, benefits, limits, eligibility rules, program links, deadlines, source claims, taxonomies and revisions are reused.
- The protected editor route requires `auth.getUser()` and a database-owned membership. Editors can preview duplicate slugs and create a transaction-safe sourced draft. Reviewers can record a dated source review, publish, unpublish, archive and reverify through one database transaction per transition. The authenticated editor RPC checks membership again inside PostgreSQL; the app needs no service key. Same-origin JSON POST is enforced. Privileged access is not provisioned by signup metadata.
- Public catalog and detail routes render RU/KK/EN search, award/country filters, sorting, source URL/check date, coverage, limits, eligibility, costs not covered, application path, deadline timezone, documents and linked programs where available. Empty, unavailable, expired and review-due information is explicit. No factual record was fabricated.
